rule: Ask whether the change is a quick fix that leaves a small mess, or a design step that keeps the code healthy, and say which it is.
why: The user policy lists this as one of the review questions, so the reviewer says which of the two the change is.
applies-when: The PR fixes a bug or adds a feature.
not-when: none
example: In invented PR 101 for owner/shop, a wrong order total is fixed by rounding at the end of the view, while the cause sits in the price code. The reviewer writes it as a quick fix and names the cause with its file and line.
