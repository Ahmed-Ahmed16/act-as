id: REV-132
rule: Put each migration, CSS block and JS block in the first part that needs it. A helper used by 2 parts goes in the lower one.
why: The user wants the pieces a part depends on to arrive with that part or before it. A migration in a later part would leave the first part running against a database that lacks its column.
applies-when: The split step places a migration, a CSS or JS block, or a shared helper that more than one group or part could use (full mode step 2, sub steps c, e and g).
not-when: Only 1 part uses the piece. It goes with that part.
example: In invented PR 101 for owner/shop, a migration adds orders.refunded_at. The refund part reads that column and the export part reads it later. The migration goes in the refund part, the first that needs it.
mode: full
trigger: When placing a migration, a CSS or JS block, or a shared helper

That is the same need order (what is needed goes first), but it is about configuration, not migrations or helpers, so it is context only, not support.
