id: REV-503
rule: Test a helper or wrapper by imagining it deleted. If the callers would not get harder to read, it hides nothing; if the mess would spread across the callers, it earns its place.
why: The deletion test asks whether removing a module moves its complexity behind a smaller interface or spreads it over the callers, and Ousterhout calls a method shallow when it does not reduce what a programmer needs to know.
applies-when: The PR adds a helper, wrapper, facade or pass through method, or leaves one in a file it touches.
not-when: none
example: In invented PR 101 for owner/shop, the new CartHelper::getItems() only returns $cart->items. Removing it changes nothing for the callers, so the reviewer writes it as a helper that hides nothing.
