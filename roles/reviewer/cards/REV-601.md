id: REV-601
rule: A key that 1 language has and another lacks is a finding of translation check 1. It is never must fix and never fails health. A gap the PR did not touch is still listed, with touched_by_pr shown as data.
why: Laravel keeps PHP language files as arrays of keyed strings and keeps JSON strings in 1 file per language, so a key can exist in 1 language and not another with no error anywhere. Only a compare of the key sets shows it.
applies-when: Running check T1 on a repo whose lang folder has 2 or more languages.
not-when: none
example: In invented PR 101 for owner/shop, lang/en.json gets the key "Order shipped" and lang/ar.json does not. Check 1 lists the key with the locales that have it (en), the locales that miss it (ar) and touched_by_pr yes. The reviewer opens the code, confirms it, and writes a finding in Known risks. It is not must fix.
mode: health, full
trigger: When running translation check T1 (a key in 1 language but not another)

extra: The key identity is the spec's. For PHP files it is the group file path plus the dotted key (a group in a folder counts). For JSON it is the whole string, from the 1 file named after the language. Laravel loads 1 JSON file per language path (line 153, and the same code at line 149 on the 11.x branch tip 9664f7d, read 2026-10-27), so several JSON files in 1 folder are not merged. Laravel does merge the 1 JSON file of a language across registered paths, such as packages (lines 151 and 160), so the reason in the spec's layout line is inexact. touched_by_pr means the language file was touched by the PR, not that this key was; whether an untouched gap stays a finding or becomes a pointer is still open (spec O20). An unreadable or invalid language file is "not checked: <file> unreadable", never "no missing keys"; Laravel itself throws on invalid JSON (line 157). Calling a gap a finding, and never must fix, come from the spec, not from Laravel. Both cited sections compared on 11.x and 12.x: same (evidence/19 and evidence/47 section checks, and anchors and quotes read on both versions on 2026-10-27).
