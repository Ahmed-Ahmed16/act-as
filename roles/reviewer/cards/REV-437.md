id: REV-437
rule: When an event or a queued listener needs data written in a transaction, check that it is dispatched or run only after the commit.
why: Laravel can wait for the commit before it dispatches an event. A queued listener has the same risk as a queued job: the queue may process it before the transaction has committed.
applies-when: Changed code fires an event, or adds a queued listener, around a database transaction.
not-when: none
example: In invented PR 101 for owner/shop, OrderPlaced is fired inside a transaction and its queued listener reads the order. Without waiting for the commit the listener may not find it. The reviewer asks for dispatch after the commit.
mode: health, full
trigger: When a changed event or listener may run before the commit
