id: REV-356
rule: A session cookie's domain stays null, so only the host that set it gets the cookie. Any domain that is not null, with or without a leading dot, needs a stated reason.
why: OWASP says a set Domain sends the cookie to that domain and all its subdomains. A too wide value, even a plain example.com, lets an attacker on 1 host reach session ids of other hosts on the same domain, and helps session fixation.
applies-when: A change sets the domain option in config/session.php, SESSION_DOMAIN, or the domain of a cookie set by hand.
not-when: The cookie is not a session or login cookie. Or the project states that its subdomains must share 1 login.
example: In invented PR 101 for owner/shop, config/session.php gets 'domain' => '.shop.example'. A forgotten test site on test.shop.example now receives the session cookie of every shopper. The same happens with 'shop.example' and no dot.
mode: security, full
trigger: When a changed file sets the session cookie domain

extra: The second source says the Domain attribute should not be set. The not-when line about subdomains that must share one login is OWASP's own exception. Whether a shared domain is safe also depends on all apps on it having the same trust level; that is the reviewer's reading of OWASP's advice not to mix security levels on 1 domain, not OWASP's words. The reviewer reads the project's stated need for shared subdomains before it calls a non null domain a finding.
