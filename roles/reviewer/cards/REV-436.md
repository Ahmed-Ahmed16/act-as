id: REV-436
rule: When a job is dispatched inside a database transaction, check whether the job needs rows from that transaction and whether it waits for the commit.
why: Laravel says a worker can pick up the job before the parent transaction has committed. The job then may not see the rows it needs.
applies-when: Changed code dispatches a job while a database transaction is open.
not-when: none
example: In invented PR 101 for owner/shop, a controller creates an order inside DB::transaction() and dispatches SendInvoice in the same block. The worker may run before the commit and not find the order. The reviewer asks for the job to wait for the commit.
mode: health, full
trigger: When a changed job is dispatched inside a transaction
