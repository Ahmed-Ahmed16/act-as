id: REV-346
rule: Run composer audit on the head lock file and read the result. If the audit could not reach its sources, write "not checked" and never a pass.
why: Composer says audit lists security advisories and also finds abandoned and malware flagged packages. OWASP says to keep an inventory of components and watch known vulnerabilities for them.
applies-when: A PR changes composer.json, composer.lock or any package manifest.
not-when: The PR changes no dependency file.
example: In invented PR 101 for owner/shop, the PR adds a package and composer audit lists 1 advisory for it. The reviewer writes the advisory as a finding with the package name.
mode: security, full
trigger: When a PR changes a dependency manifest or lock file
kind: source-advice
source: Composer docs, command line, audit, https://getcomposer.org/doc/03-cli.md#audit, read 2026-10-27 ; second source: OWASP Top 10 2021, A06 Vulnerable and Outdated Components, How to Prevent, https://owasp.org/Top10/2021/A06_2021-Vulnerable_and_Outdated_Components/#how-to-prevent, read 2026-10-27
anchor: "The command also detects abandoned packages and packages flagged as malware"
status: approved

extra: The not checked rule comes from ticket 02: composer audit needs the network and exits 100 when it cannot reach it, and the option --ignore-unreachable turns that into a pass. The Composer page lists exit codes 0 and 1 only, so the 100 is our own finding. Lock files leave the size count but never this check (spec).
