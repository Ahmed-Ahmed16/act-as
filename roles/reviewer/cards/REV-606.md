id: REV-606
rule: A key no code uses is a pointer, never a finding. List it in 1 of 2 groups: "passed through a variable" or "no trace". It never fails health. "No trace" is not proof of no use while dynamic_call_sites is not empty.
why: A dead key scan matches only calls whose key is typed out in the call. A key built at run time cannot be matched, so calling it plainly unused would send the reader to delete a key that may be in use.
applies-when: Running check T6 on a lang folder that has keys with no literal use found.
not-when: none
example: In invented PR 101 for owner/shop, the PR adds the key "status.shipped" and the code calls __('status.' . $state). The key goes in "passed through a variable". A second key "promo.banner" has no call anywhere and goes in "no trace".
mode: health, full
trigger: When running translation check T6 (keys with no use found)

extra: The README lists the function calls the scanner understands (__, trans, trans_choice, Lang::get, Lang::has). Its Requirements section shows `__($key)` as "no key is detected", which is the variable limit (read 2026-10-27), and the spec says the same of both tools. The tool's own variable group holds only unused keys that start with a typed out prefix of a dynamic call; a key used through a bare `__($key)` falls in "no trace". The split into 2 groups and the pointer status are the spec's. The second tool was not proved offline; only the first was. A call site with a variable key is "not checked" in the packet.
