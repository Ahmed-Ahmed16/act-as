id: REV-509
rule: A comment should usually explain why the code exists, not what it does.
why: Google says that a comment explaining what the code does means the code should be made simpler, and keeps comments for reasons the code cannot hold.
applies-when: A pointer sent the reviewer here, and the PR adds or changes comments.
not-when: The comment sits on code such as a regular expression or a complex algorithm, where explaining what it does helps; these are Google's examples, not a closed list.
example: In invented PR 101 for owner/shop, the comment `// loop over items` sits above a foreach over items. The reviewer writes that it says what, not why, and suggests removing it. A comment that says why a refund waits 3 days stays.
