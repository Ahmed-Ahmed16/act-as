id: REV-209
rule: Match both the old path and the new path of a renamed file against every Covers line.
why: A rename must not move a file out of the area that covers it, and a file moved into an area must be judged there.
applies-when: A changed file in the PR was renamed or moved.
not-when: none
example: In invented PR 101 for owner/shop, app/Orders/Cancel.php moves to app/Misc/Cancel.php. The ordering page covers app/Orders/, so the ordering area is touched through the old path.
mode: business, full
trigger: When mapping a renamed file to areas
kind: user-policy
source: user decision, reviewer v1 spec, the business rules pages, user story 69, approved 2026-10-25
status: approved

extra: no external source found. Context only: GitHub REST compare two commits, https://docs.github.com/en/rest/commits/commits#compare-two-commits, read 2026-10-27, gives a previous_filename for renamed files, so both paths exist. Matching both is this project's rule.
