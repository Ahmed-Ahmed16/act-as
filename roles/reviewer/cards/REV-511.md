id: REV-511
rule: Things that change for the same reason should sit together, so a change to 1 rule touches 1 place and not many.
why: Martin writes the single responsibility principle as gathering what changes for the same reasons and separating what changes for different reasons.
applies-when: The PR changes a business rule, or a fixed list or single limit (a size, a count) that is typed in 2 or more places; the health step 14 search finds those copies. A pointer for many routes on 1 controller also sends the reviewer here.
not-when: 2 equal lists mean different things, so a change to one never needs a change to the other.
example: In invented PR 101 for owner/shop, the allowed image types are typed in the upload controller and again in the avatar form request. The reviewer counts 2 places to change and names both with their file and line.
