id: REV-431
rule: When a migration changes a column, check that it repeats every modifier the column should keep. A modifier left out is dropped.
why: Laravel says a column change replaces the column definition, so any modifier you do not write again (such as nullable or default) is lost.
applies-when: A changed migration calls change() on an existing column.
not-when: none
example: In invented PR 101 for owner/shop, a migration does $table->string('name', 100)->change() on a column that was nullable with a default. After the change the column is not nullable and has no default. The reviewer reports it.
mode: health, full
trigger: When reading a changed migration that modifies a column
kind: source-advice
source: Laravel 12.x docs, Migrations, Modifying Columns, https://laravel.com/docs/12.x/migrations#modifying-columns, read 2026-10-27
