id: REV-304
rule: Every action that creates, changes or deletes data is covered by a permission check. One central check, such as route or group middleware, is better than a check inside each method. A policy before() method is not a check for an ability the policy has no method for.
why: OWASP prefers a global, application wide permission check over one in each method, because a single missed check is enough for an attacker. Laravel says the before method of a policy is not called when the policy class has no method named like the ability being checked.
applies-when: A changed POST, PUT, PATCH or DELETE route or a write method in a controller, job or command.
not-when: The route is a server to server callback guarded by a signature check and not by a user permission, or the action changes nothing (a read).
example: In invented PR 101 for owner/shop, OrderPolicy has a before() method that lets admins do everything. The PR adds a new ability, export, with no policy method for it. The reviewer finds out what decides export, because before() is never called for it.
mode: security, full
trigger: When a changed write action relies on a policy
