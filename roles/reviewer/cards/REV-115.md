id: REV-115
rule: Never compare the PR head with the current tip of the base branch, or with a local or freshly fetched default branch. Use the frozen merge base.
why: A two dot compare moves whenever the base branch moves, so the PR would get blamed for changes it did not make.
applies-when: Choosing what to diff the PR head against.
not-when: none
example: In invented PR 101 for owner/shop, release gained an unrelated fix after the PR branched. A two dot compare with release would show that fix as deleted by the PR.
mode: all
trigger: When choosing what to compare the PR head with
kind: source-advice
source: GitHub Docs, comparing branches in pull requests, about three dot comparison, https://docs.github.com/en/pull-requests/reference/branches#about-three-dot-comparison-on-github, read 2026-10-26
anchor: "the diff changes when the base branch is updated"
