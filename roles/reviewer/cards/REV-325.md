id: REV-325
rule: The session id is renewed when a user logs in and when their rights change.
why: OWASP says the session id must be renewed after any change of privilege, above all at login. Otherwise an attacker who set the id before login can use it afterwards (session fixation).
applies-when: A change adds or edits the login code, a switch of user, or a change of role.
not-when: The framework's own login code is used unchanged.
example: In invented PR 101 for owner/shop, the new login method signs the user in but never regenerates the session. An attacker who planted a session id in the victim's browser becomes the victim after login.
mode: security, full
trigger: When a changed flow signs a user in or changes their rights
kind: source-advice
