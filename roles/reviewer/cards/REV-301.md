id: REV-301
rule: Every action that takes a record id from the client must check that this user may do this action on this record. Being logged in is not enough.
why: OWASP says to run the authorization check in every function that uses a client input to reach a record. A user who changes the id in the request must not reach someone else's record.
applies-when: A changed route, controller, job or command loads a record by an id that came from the request.
not-when: The record is public by design, or the code takes the user's own record from the session and not from a request id.
example: In invented PR 101 for owner/shop, GET /invoices/{id} loads the invoice with findOrFail($id) and returns it. Nothing checks that the invoice belongs to the signed in user, so user 17 changes the id to 18 and reads another customer's invoice.
mode: security, full
trigger: When a changed action loads a record by an id from the request
