id: REV-353
rule: 2 requests at the same time must not both pass a check and then both update. Use a serializable transaction, a row lock, or a single conditional update, and check the affected row count.
why: OWASP says that with the default isolation level the check and the update are 2 separate steps, so another request can get in between them.
applies-when: A change reads a value, checks it, then writes it, such as a balance, a stock count or a status.
not-when: The value is only read, or a single conditional update does the check and the write in one statement.
example: In invented PR 101 for owner/shop, 2 orders read stock 1, both see enough, and both subtract. Stock goes to minus 1. The fix is UPDATE ... WHERE stock >= 1 and a check of the affected rows.
mode: security, full
trigger: When a change checks a value and then updates it
