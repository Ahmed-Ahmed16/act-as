id: REV-432
rule: Check the timestamp in the file name of a new migration. Migrations run in file name order, so one that needs a table or column must come after the one that creates it.
why: Laravel puts a timestamp in each migration file name so that it can work out the order of the migrations.
applies-when: A PR adds a migration file.
not-when: none
example: In invented PR 101 for owner/shop, a new migration adds a foreign key to the orders table, but its file name is dated before the migration that creates orders. On a fresh database it fails. The reviewer reports it.
mode: health, full
trigger: When reading the file name of a new migration
