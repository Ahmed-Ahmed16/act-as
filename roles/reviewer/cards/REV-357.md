id: REV-357
rule: The session lifetime is set to what the project says it needs, not longer. A change that sets or raises it is checked against the project's stated need for staying signed in.
why: OWASP says it is mandatory to set an expiration timeout for every session, and the shorter the interval, the less time an attacker has to use a stolen session id. It gives no single limit, because the right value depends on how critical the app is.
applies-when: A change sets or raises the lifetime option in config/session.php or SESSION_LIFETIME.
not-when: The cookie is not a session or login cookie. Or the project states why a long session is needed and the change stays inside it.
example: In invented PR 101 for owner/shop, config/session.php gets 'lifetime' => 525600 (1 year, in minutes). The value is 1 setting for the whole app, admin area included. A session id taken from a lost laptop still works months later.
mode: security, full
trigger: When a changed file sets the session lifetime

extra: Laravel's lifetime option is an idle timeout. Laravel has no built in absolute timeout, so this card does not cover one. No limit is set by this card. The OWASP ranges below are examples that depend on the app: idle timeout 2 to 5 minutes for high value apps and 15 to 30 minutes for low risk ones (stated in both OWASP pages), and an absolute timeout of 4 to 8 hours for an app an office worker uses all day (in the Session Expiration section of the Session Management sheet). The reviewer compares the new value with the project's stated need; if the project states none, the number is `___` and the finding is a lead. That page does not describe the lifetime option.
