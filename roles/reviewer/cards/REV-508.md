id: REV-508
rule: If a piece of changed code is too hard for you to follow, say so and ask the author to clarify it.
why: Google says that code a reviewer cannot understand is very likely unclear to other developers too, so asking for clarity helps the people who read it later.
applies-when: The reviewer reads changed code and cannot say what it does after a fair read.
not-when: The reviewer understands the code but is not the right person for 1 part, such as security; that is a different step.
example: In invented PR 101 for owner/shop, a 20 line closure chains 5 array calls and the reviewer cannot say what the result holds. The reviewer writes that the author should clarify it, with the file and line.
