id: REV-515
rule: A change must not leave the code it touches harder to work with than before. Check whether the PR cleaned up the code around it or bolted onto it.
why: Google says the reviewer's duty is that code health does not decrease over time, and that small complexities add up.
applies-when: The PR changes a file that already had a problem in the touched area, such as a long method or a copied block, and adds to it. Read the whole touched file for this (health step 2).
not-when: The problem sits in a part of the file the PR did not touch.
example: In invented PR 101 for owner/shop, the PR adds a 4th payment type branch to a method that already has 3 copies of the same fee code. The reviewer writes that the change adds to the mess, with the file and line.
