id: REV-340
rule: Logs never hold passwords, tokens, session ids or personal data unless the value is removed, masked or hashed first.
why: OWASP lists data that should usually not be written to logs directly: session ids, access tokens, passwords, personal data, payment data, and keys. They are to be removed, masked, sanitized, hashed or encrypted.
applies-when: A changed line writes request data, a user, a provider reply or an exception to a log (Log::, logger, report).
not-when: The logged value holds none of these.
example: In invented PR 101 for owner/shop, the payment code runs Log::info('reply', $response->all()). The log file now holds card holder data and the provider's token.
mode: security, full
trigger: When a changed line writes data to a log
