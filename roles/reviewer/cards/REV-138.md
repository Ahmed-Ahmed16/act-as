id: REV-138
rule: Every part opens against main after the parts it needs are merged. Read the workflow branches filter and record it as the reason: where CI runs only for pull requests into main, a part opened on another part's branch gets no CI.
why: GitHub can limit a workflow to pull requests that target given branches, and says CI often runs only for the bottom pull request of a chain. The user settled the opening rule in amendment B24, and the plan reads the branches filter to say so.
applies-when: The split step writes which branch each part opens against (full mode step 2, sub step i).
not-when: none
example: In invented PR 101 for owner/shop, the workflow runs on pull requests into main only. Part 2 needs part 1, so part 2 opens against main after part 1 is merged, not against part 1's branch. Part 3 needs nothing and opens against main at once.
mode: full
trigger: When writing which branch each part opens against
