id: REV-127
rule: Group changed files by the entry point that reaches them: a route, a command, a scheduled job or a screen. Never group by file kind, such as all controllers, all views or all migrations.
why: The user wants each group to be 1 behaviour, so an author can open it as 1 PR and a reviewer can read it as 1 story. A group made of one file kind cuts across behaviours.
applies-when: The split step forms the groups of a PR that is over the cap (full mode step 2, sub step d).
not-when: none
example: In invented PR 101 for owner/shop, the groups are "the refund route and its screen" and "the weekly report command and its schedule line". They are not "controllers", "views" and "migrations".
mode: full
trigger: When forming the groups of a split plan
kind: user-policy
source: user decision, reviewer v1 spec, the split plan contract (Groups come from entry points) and user story 47, approved 2026-10-25
