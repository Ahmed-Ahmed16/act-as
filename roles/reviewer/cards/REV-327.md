id: REV-327
rule: A recovery or fallback path for the second factor may exist, but it must not give an attacker a way to skip it. No path gives a weaker way in than the second factor.
why: OWASP says users who lose a factor need a way back in, and that this way must not become a bypass for an attacker. It also says to disable legacy login endpoints that cannot enforce MFA.
applies-when: A change adds or edits a 2 factor flow, a recovery path, an API login or a legacy login route.
not-when: The app has no 2 factor login.
example: In invented PR 101 for owner/shop, the PR adds POST /api/login that returns a token after the password, and skips the 2 factor step the web login needs. Anyone with the password gets in.
mode: security, full
trigger: When a changed login or recovery path touches 2 factor
kind: source-advice
