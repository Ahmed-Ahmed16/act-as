id: REV-602
rule: A key the code uses but a language file lacks is a finding of translation check 2. It is never must fix and never fails health.
why: When Laravel finds no translation it returns the key itself, so the page shows the key text and nothing fails. A fallback language can hide the gap on screen too, so a page that looks fine can still have a missing key.
applies-when: Running check T2 on the scanned code: every call to __(), trans(), trans_choice() or the other translator calls with a key typed out in the call, not only changed lines.
not-when: The key is passed through a variable. The script cannot read it, so that call site is "not checked", not a finding.
example: In invented PR 101 for owner/shop, a Blade view calls __('Refund requested') and lang/ar.json has no such key. Check 2 lists the key with the file and line of the call. The reviewer opens the view, confirms it, and writes a finding in Known risks. It is not must fix.
mode: health, full
trigger: When running translation check T2 (a key used in code but missing from a language file)
