id: REV-424
rule: A design regression is must fix only when the PR shows a burden (it made the 2nd copy of a rule or payload, or the cost to add rose from base to head) and you can name a small fix in 1 line. Otherwise it is a pointer or a lead.
why: The spec bans a vague "bad design" fail. The burden and the fix must both be shown.
applies-when: A design regression is found in a changed area.
not-when: none
example: In invented PR 101 for owner/shop, the PR copies the list of allowed upload types into a 2nd file. The burden is shown (the 2nd copy) and the fix is "move the list to config/uploads.php", so it can be must fix. A design opinion with no burden stays a pointer.
