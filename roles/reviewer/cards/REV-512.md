id: REV-512
rule: A class should answer to 1 person or 1 tightly coupled group, who stand for 1 narrow business function.
why: Martin says the single responsibility principle is about people: a change request for 1 business function should not break code another function depends on.
applies-when: The PR adds a method or a route to a class that already serves a different business function, such as a controller that handles carts, invoices and user settings.
not-when: All the methods of the class serve the same business function and would be changed on the same request.
example: In invented PR 101 for owner/shop, OrderController gets a new invoice export method next to its cart methods. The reviewer asks whether finance and the shop team would both ask for changes to this class, and names both groups.
