id: REV-217
rule: If new code inside an existing route, screen, command or job does not follow a gap rule, make it a finding (not a must fix finding).
why: The PR adds to the gap quietly, but the door was already open, so this is lower than a gap made worse.
applies-when: A rule marked gap, and the PR adds code in an existing door that does not follow it.
not-when: none
example: In invented PR 101 for owner/shop, R10 (gap) says a cancel needs a login, but the old cancel route does not check it yet. The PR adds a line inside that route that saves a cancel reason, and the line trusts the request like the rest of the route. No check is removed or weakened, the reach is the same, and there is no new door. It is a finding, not a must fix finding.
mode: business, full
trigger: When new code in an existing door does not follow a gap rule
