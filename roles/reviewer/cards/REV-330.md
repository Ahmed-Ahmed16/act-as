id: REV-330
rule: On a site served only over HTTPS, session cookies carry the Secure flag. On a mixed site, null sets it automatically for HTTPS requests.
why: OWASP says the Secure flag is needed so the session id is not sent over plain HTTP, where a man in the middle could read it.
applies-when: A change touches config/session.php or sets a cookie by hand.
not-when: The cookie is not a session or login cookie.
example: In invented PR 101 for owner/shop, config/session.php gets 'secure' => false on a site that is HTTPS only. A downgraded request sends the session id in clear text.
mode: security, full
trigger: When a changed file sets the secure cookie option
kind: source-advice
source: OWASP Laravel Cheat Sheet, Cookie Security and Session Management, https://cheatsheetseries.owasp.org/cheatsheets/Laravel_Cheat_Sheet.html#cookie-security-and-session-management, read 2026-10-27 ; second source: OWASP Session Management Cheat Sheet, Secure Attribute, https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html#secure-attribute, read 2026-10-27
