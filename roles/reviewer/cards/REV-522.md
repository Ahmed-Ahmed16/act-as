id: REV-522
rule: For a refactor or cleanup, ask for a record of what the code did before, and proof that it still does the same.
why: Fowler defines a refactoring as a change that leaves observable behaviour as it was, and Google says to check the tested behaviour is the same before and after.
applies-when: The PR is a refactor or cleanup, meaning its stated aim is a better structure and no new behaviour.
not-when: The PR changes behaviour on purpose; then it is not a refactor and the normal test questions apply.
example: In invented PR 101 for owner/shop, the PR moves the price code into a new class. The reviewer checks for tests that pass unchanged on base and head, or for the output of both on 1 case, and writes "no record of old behaviour" if neither is there.
