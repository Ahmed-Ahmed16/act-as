id: REV-513
rule: Keep business rules apart from the web layer, the database and the framework, so each can be read and changed alone.
why: Martin says business rules should not know the database schema, and Fowler says presentation logic and domain logic are easier to understand when separate.
applies-when: The PR puts a business rule, such as a discount or a refund limit, in a controller, a view, a query or a framework hook. A pointer for many routes on 1 controller also sends the reviewer here, together with question 11, until the question 12 card loads.
not-when: none
example: In invented PR 101 for owner/shop, the rule that a coupon cannot be used twice sits in a Blade view as an if on a database column. The reviewer asks for the rule to live in a class with no view or query code.
