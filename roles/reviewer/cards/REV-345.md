id: REV-345
rule: A callback that was already processed is refused. Keep the ids of processed events and check the timestamp, because a valid signature can be replayed.
why: OWASP says a captured delivery still carries a valid signature, so the signature alone does not stop it being processed again. The receiver also needs a freshness check and a record of processed events.
applies-when: A change adds or edits a webhook or payment callback handler.
not-when: The handler only reads data and changes nothing.
example: In invented PR 101 for owner/shop, the provider sends the paid event twice. The handler marks the order paid and adds the stock again each time. The reviewer asks where processed event ids are stored.
mode: security, full
trigger: When a callback handler changes data
kind: source-advice
source: OWASP Webhook Security Cheat Sheet, Replay Attack Protection, https://cheatsheetseries.owasp.org/cheatsheets/Webhook_Security_Cheat_Sheet.html#replay-attack-protection, read 2026-10-27
