id: TST-403
rule: Before a canary is watched, pick the few metrics that most show user harm, such as failed requests and slow responses, and leave the rest out.
why: The source says too many metrics bring diminishing returns and can wear down trust in the release process.
applies-when: A canary is about to be watched and the tester sets which signals to check.
not-when: No exception is stated on the cited page.
example: For a web front end the tester watches the error ratio and response time, and leaves CPU use out, because CPU can rise without any harm to users.
