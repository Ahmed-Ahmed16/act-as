id: TST-502
rule: Avoid implying that all bugs were found. Define what kind of testing is complete, then state what you tested and why.
why: Clients may read an unqualified claim of completion as saying every bug was found.
applies-when: When you report test status or when someone asks whether testing is finished.
not-when: You clearly state a narrower meaning, such as completing the agreed tests.
example: Instead of "login is fully tested," write "login tested for the password and lockout cases; SSO login not tested."
mode: explore, site, code
trigger: before writing a test status or saying testing is done
