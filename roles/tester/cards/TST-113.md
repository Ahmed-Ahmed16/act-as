id: TST-113
rule: When a test passes on some runs and fails on others, find the cause first; do not delete the test to get a green result.
why: Deleting it hides a real gap, and a known failure can hide other failures in the same run.
applies-when: A test fails only sometimes, or only on another machine, or only when run with other tests.
not-when: A test with the same result on every run is not the erratic behaviour described here.
example: A test passes alone but fails after another test changes the same database row; the fix is to make each test create its own row.
mode: code
trigger: when a test fails on one run and passes on the next, or fails only on a teammate's machine
