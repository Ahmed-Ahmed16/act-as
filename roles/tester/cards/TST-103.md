id: TST-103
rule: A test must give the same result on every run without a manual reset, so clean up any state it leaves behind.
why: A test that passes once and fails the next run teaches the team to ignore the red result.
applies-when: A test writes to a database, a file, a service or any other state that survives the test.
not-when: A test that uses only local variables and objects in memory; those usually repeat without extra work.
example: A test that inserts a row and expects an empty table on the next run fails on the second run, so it must delete its row at the end.
mode: code
trigger: when writing a test that uses shared state, and when a test fails only on a second run
