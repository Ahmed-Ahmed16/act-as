rule: Write bug reports to support repair, by making the full impact of the problem clear.
why: The quality of the research and writing often changes the chance that the bug will be fixed.
applies-when: Whenever you file a bug report.
not-when: The lesson says some bugs will never be fixed, and that the tester is not responsible for making every one get fixed.
example: A slow report page gets a report that gives the number of users it hits and the time it costs, so the manager can weigh the fix against other work.
