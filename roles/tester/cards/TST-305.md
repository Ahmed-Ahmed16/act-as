id: TST-305
rule: Work directly with end users to collect real examples of the behavior they want, then turn them into tests.
why: Concrete examples improve communication and reduce misunderstandings about what the system should do.
applies-when: The team is defining the expected behavior of a feature or story.
not-when: No exception is stated in the summary.
example: Illustration: a tester sits with two teachers, records how they upload a class roster, and writes each step as an example test.
mode: code
trigger: Defining expected behavior before coding a story
