id: TST-111
rule: When a test is hard to understand at a glance, simplify it so its behaviour is clear.
why: An unclear test can hide its own bugs and makes every later change to it slower.
applies-when: Reviewing a test whose purpose is not clear after one read.
not-when: A test that is long only because the scenario is a real end to end sequence of steps.
example: A test with 30 lines of setup and three different checks is split into one test per check, with the setup moved into a named helper.
mode: code
trigger: when reviewing a test someone wrote, and after a failure that took long digging to understand
kind: source-advice
