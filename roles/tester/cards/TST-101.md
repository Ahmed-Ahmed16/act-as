id: TST-101
rule: Give each test a single condition, so one test checks one thing and a failure points at one cause.
why: When a test checks many things, a red result does not say which behavior broke.
applies-when: Writing a new test method, or splitting a test that checks several conditions in one run.
not-when: A long customer style scenario that really is a sequence of steps; the book allows longer test methods there.
example: A test that checks both the flight number and the airline code becomes two tests, one per condition.
mode: code
trigger: before writing a test, and when reviewing a test someone wrote
kind: source-advice
