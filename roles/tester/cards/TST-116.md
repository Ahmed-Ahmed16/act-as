id: TST-116
rule: Move setup that is not the point of the test into a named helper, and keep in the test body only the details that matter to the result.
why: When every test spells out its setup, one constructor change breaks many tests and hides what each test is about.
applies-when: Several tests repeat fixture setup, or setup includes details not needed to understand the result.
not-when: The setup detail is the very thing being tested; keep it visible in the test body.
example: A test for a rejected invoice calls a helper that builds a valid invoice, then changes only the field under test.
mode: code
trigger: before writing setup code, and when reviewing a test with long setup
kind: source-advice
