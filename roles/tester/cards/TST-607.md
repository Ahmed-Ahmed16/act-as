id: TST-607
rule: Raise a pull system for the test environment, so the tester decides when a new build lands on it.
why: The chapter says a build pushed in mid session can overwrite the build under test, and then the testing often has to start again from scratch.
applies-when: A new build could replace the build under test in the middle of a test session.
not-when: No exception is stated in the chapter.
example: Illustration: the tester is 40 minutes into a session on build 14 when an automatic push would swap in build 15. With a pull setup, build 14 stays until the tester asks for the next one.
