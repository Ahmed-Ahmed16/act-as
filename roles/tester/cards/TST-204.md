id: TST-204
rule: Plan checks for speed, security and load from the start of the work, not in the last days before release.
why: Some qualities matter as much as features: a slow page fails users even when every feature works.
applies-when: The story touches response time, data handling, login, or a shared system under load.
not-when: A small text or layout change with no effect on speed, data or security; a full load test there is wasted effort.
example: A checkout change gets a response time check on a staging copy in the same iteration, not in the final week.
mode: code, site
trigger: planning checks for a story that touches speed, security or load
