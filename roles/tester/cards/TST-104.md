id: TST-104
rule: Clean up what a test creates with one generic cleanup mechanism, not with separate cleanup code written in each test.
why: Hand written cleanup gets missed in some test, and the leftover data then causes failures later.
applies-when: A test creates records, files or other persistent items that must be removed afterwards.
not-when: The fixture lives only in memory and disappears when the test ends.
example: A test that creates three orders registers each one with a cleanup list, so all three are removed even when an assertion fails.
mode: code
trigger: when writing a test that creates persistent data
