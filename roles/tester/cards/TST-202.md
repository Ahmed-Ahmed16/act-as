id: TST-202
rule: Turn the customer's examples into tests that the business experts can read.
why: Each example states the expected behavior in the business's own words, so a wrong expectation shows up before the code is built.
applies-when: A story comes with examples from the customer team.
not-when: The check is about how the feature feels to a user or how it compares with a competitor; that needs an exploratory check.
example: The story says a coupon applies once per order; the tester writes that sentence as a test and adds a second order with the same coupon, which must be refused.
mode: code
trigger: turning a story's examples into tests before coding starts
