id: TST-207
rule: Keep browser driven checks few, and count each one as costly to maintain.
why: Page changes break browser checks often, and a large browser suite can take hours instead of minutes.
applies-when: Adding a new check that drives the site through the browser, such as a login or checkout path.
not-when: A critical user path that no lower level check can cover; keep that one, and keep the number small.
example: The site suite keeps browser checks for login, search and checkout, and covers the other rules with API checks.
mode: site
trigger: adding a new browser check to the smoke or regression suite
