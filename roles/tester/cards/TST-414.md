id: TST-414
rule: Typically, mock dependency API calls in unit tests, and test interactions with live dependencies later in integration tests.
why: Fake dependencies can test error cases that are hard to trigger live, and real calls check that the fakes match reality.
applies-when: A test is being put into the build stage of a pipeline.
not-when: No exception is stated on the cited page.
example: A test of a storage API error gets a fake error in the build stage. A real call to a test environment runs in the integration stage.
mode: code
trigger: when deciding which checks go in the build stage
kind: source-advice
source: Clare Liguori (AWS), "Automating safe, hands-off deployments", Build and unit tests, https://aws.amazon.com/builders-library/automating-safe-hands-off-deployments, read 2026-10-13
