id: TST-105
rule: Do not put test only hooks or branches into the product code; the test brings its own stand in from the outside.
why: Test code inside the product can ship to users, and it can hide what the real code does.
applies-when: A test needs to control a dependency or needs a test hook.
not-when: The product already has a normal seam for passing in a dependency for real use; using that seam is not a test hook.
example: A test that needs a fixed clock receives a clock object from outside, instead of adding a testing flag to the product's time function.
mode: code
trigger: when a test needs something from the product code that the product does not expose, and when reviewing a change to product code made for tests
kind: source-advice
