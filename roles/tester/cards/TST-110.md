id: TST-110
rule: Replace an if guard in a test with an assertion that fails the test with a clear reason.
why: A failed assertion says what was expected, while a branch that quietly skips the check can let a test pass when it should fail.
applies-when: A test must confirm that the code under test returned a usable value before it reads inside that value.
not-when: The statements that follow stay safe when the condition is false, so no guard is needed to prevent an error.
example: Instead of "if the result is not null, check the name", the test asserts that the result is not null, then checks the name.
mode: code
trigger: when writing a test that reads a value returned by the code under test, and when reviewing a test with if statements
