id: TST-201
rule: For Quadrant 1 coverage, use unit and component tests, usually automated in the language of the application and normally run with each code check in.
why: They give the fastest signal on the code's internal quality, before a change reaches the wider build.
applies-when: A new function, class or small group of classes is being changed.
not-when: The question is whether a business person would accept the behavior; that calls for a business check, not a unit test.
example: A new discount function gets unit tests for 0, 10 and 100 percent inputs before the change is merged.
mode: code
trigger: writing tests for new or changed code
