id: TST-112
rule: Include descriptive assertion messages when they help identify a failure; strongly consider them when a test has several assertions, above all of the same type, or runs from a command line runner.
why: When a test fails in a command line run, the message tells you which check failed without a long debug session.
applies-when: Several assertions appear in one test, above all of the same type, or a command line runner is used.
not-when: A test with one assertion whose failure output already names the value and the expected value.
example: Three equality checks on a line item get the messages "invoice", "product" and "quantity", so the failure names the field that differs.
mode: code
trigger: when writing assertions in a test, and when a failure log does not show which check failed
