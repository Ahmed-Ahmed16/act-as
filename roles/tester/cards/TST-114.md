id: TST-114
rule: When a test breaks after a change that should not touch what it checks, find out why the test is tied to unrelated code before you fix it.
why: Tests that break for unrelated reasons make every product change cost extra repair work.
applies-when: A test that used to pass fails after an unrelated change, or fails to compile after a signature change.
not-when: The change really did alter the behavior the test checks; then update the expected result and say why.
example: A test fails to compile after a constructor gains an optional argument; the test builds its object through one creation helper, so only that helper needs updating.
mode: code
trigger: after a test breaks following a code change, and before updating the test
