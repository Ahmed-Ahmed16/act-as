id: TST-208
rule: Automate regression checks for existing behavior, so every build reports when something old breaks.
why: Automated checks flag a break within minutes at the unit level and within hours at higher levels, which makes changes safe to make.
applies-when: A change touches code that existing behavior depends on, and that behavior can be checked by a script.
not-when: A single check that will never be run again; it can stay manual.
example: After a change to the date formatter, the unit tests fail and name the broken function before any manual test starts.
mode: code, site
trigger: a change touches code that existing behavior depends on
