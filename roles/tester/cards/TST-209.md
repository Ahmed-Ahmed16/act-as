id: TST-209
rule: Keep the suite that runs on every code change short, and move the slow checks to a nightly run.
why: The book says most agile teams find a build over 8 to 10 minutes unworkable, because changes pile up while people wait.
applies-when: The full run on each change takes long enough that changes start to pile up while people wait.
not-when: The slow check is the only check on a serious risk; keep it and make it faster rather than moving it to nightly.
example: A 40 minute run on every change keeps its unit set on every change, and moves the database and browser set to a nightly run.
mode: code
trigger: a suite run is slow and delays feedback
