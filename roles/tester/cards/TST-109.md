id: TST-109
rule: Treat control structures (if, loops, switch) in a test method as a serious warning sign.
why: A test that may run different steps is hard to trust, because nobody can tell which path ran or whether the right one ran.
applies-when: Writing or reviewing a test that contains a branch or a loop.
not-when: No exception is stated on the cited pages.
example: A test that loops over a flight list and breaks when it finds one flight should use a helper that selects the flight, then assert on that flight directly.
mode: code
trigger: when reviewing a test someone wrote, and before adding a branch to a test
kind: source-advice
source: xUnit Test Patterns, Meszaros, 2007, chapter 15 "Code Smells", section "Conditional Test Logic", printed page 200, PDF page 263, read 2026-10-13
anchor: "View any control structures within a Test Method with extreme suspicion"
