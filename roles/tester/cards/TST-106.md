id: TST-106
rule: Use a stub to feed the code under test the input it would get from a dependency, including bad input and errors.
why: A real dependency may not give the error case on demand, so the test cannot reach that path any other way.
applies-when: The code under test calls a dependency, and the test must force a specific return value or an exception.
not-when: The test must check what the code sent to the dependency; then a spy or a mock fits better (see TST-107).
example: A stub for a time provider throws an exception, so the test can check that the page shows an error text.
mode: code
trigger: before writing a test that needs a dependency to return a specific value or fail
