id: TST-117
rule: Build only the objects and values a test needs to explain its result, and hide the rest inside helpers.
why: Extra setup is noise for the reader, slows the test, and hides what really causes the result.
applies-when: Designing the setup for a test or for a helper it calls.
not-when: A boundary value or any value the check depends on; keep those visible even if they look like detail.
example: A discount test needs a cart with one item at a given price; it does not need a customer address, so the address is left out.
mode: code
trigger: before writing a test's setup, and when reviewing a setup block that runs long
kind: source-advice
