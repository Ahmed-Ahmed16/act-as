id: TST-118
rule: Write each test in four visible parts, in order: setup, exercise, check, and cleanup.
why: A reader can see what is set up, what runs, and what is expected, without tracing the code.
applies-when: Writing a test method, or reviewing one where setup, action and checks are mixed together.
not-when: No exception is stated on the cited pages. The 4 phases remain the test structure.
example: A login test sets up a user, calls log in, then checks the returned session, and removes the user last, after the checks.
mode: code
trigger: before writing a test, and when reviewing a test where setup and checks are interleaved
