id: TST-021
rule: Keep regression evals near a 100% pass rate, and let capability evals start at a low pass rate.
why: Regression evals catch backsliding, while capability evals give the team a target to climb.
applies-when: setting up an eval suite for an AI feature
not-when: an eval already sitting at 100%, which gives no signal, so harder tasks are needed instead
example: a refund policy eval starts near 20% as a capability eval, while a login regression eval sits at 100%
mode: code
trigger: when setting up an eval suite
kind: source-advice
