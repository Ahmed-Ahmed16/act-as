id: TST-107
rule: Use a spy or a mock when the test must check what the code under test sent out to a dependency.
why: Checking only the returned value misses calls made on the side, such as a charge request or a log entry.
applies-when: The behavior to verify is a call the code makes to another component.
not-when: The result shows up in a return value or in saved data; a plain check of that result is enough.
example: A checkout test uses a spy in place of the payment gateway, then checks that exactly one charge was requested with the right amount.
mode: code
trigger: before writing a test that must confirm a call to another service
