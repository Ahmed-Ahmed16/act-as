id: MGR-003
rule: Write each step's done line as a concrete event that is either fully done or not done. Never use a percent ("90% finished") or a vague claim like "planning complete".
why: Vague milestones let progress be claimed without being real; the source says "planning complete" can be proclaimed almost at will.
applies-when: Writing the next steps, or judging whether an open item is done.
not-when: none.
example: "Card gate 90% done" becomes "test_cards.py passes on main".
mode: status, plan
trigger: before writing a done line for any step
kind: source-advice
source: The Mythical Man-Month, Brooks, Anniversary Edition 1995, chapter 14 "Hatching a Catastrophe", section "Milestones or Millstones?", printed page 154, PDF page 156, read 2026-10-19
anchor: "Milestones must be concrete, specific, measurable events, defined with knife-edge sharpness."
